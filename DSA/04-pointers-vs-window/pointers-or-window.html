Pointers or Window?

Both patterns search the same space, the grid of every (start, end) pair, and both finish in O(n) by throwing away a whole row or column per step. What differs is the question they ask and the fact that makes the throw-away legal.

Two pointersAsks what's at the two ends. Legal because the input is sorted.
Sliding windowAsks what's inside the range. Legal because validity is monotone, for example no negative values.
NeitherCan't sort and need positions: a hash map. Negatives with a sum target: prefix sums.

One grid, two staircases

Day 1 · both are O(n) for the same reason

Brute force on an array of n items looks at every cell of an n×n grid: a pair (i, j) for two pointers, a window [l..r] for a sliding window. That is about n²/2 cells.

Both patterns do the same trick. They compute one cell, prove that a whole row or column around it can't hold a better answer, and discard it without looking. Each step deletes a line, so the walk ends after about n steps (two pointers) or 2n steps (window). Step both panels and watch the unknown counter fall.

Why the skip is safe, and how to break it

Day 1 and Day 4 · the precondition is the pattern

Every elimination in section 1 rested on one inequality. Learn the inequality and you know when each pattern is allowed.

Two pointers needs order

If a is sorted and a[i] + a[j] < target, then every other partner j′ < j left in row i is no bigger than a[j]:

a[i] + a[j′] ≤ a[i] + a[j] < target

So row i is dead. The mirror argument kills column j when the sum is too big.

A window needs monotone validity

If every value is ≥ 0 and sum(a[l..r]) < S, then every shorter window ending at r only loses values:

sum(a[l′..r]) ≤ sum(a[l..r]) < S for l′ > l

So column r is dead. When the window is valid, the rest of row l is only longer, so it is dead too.

Now remove the precondition and run the same code. The left panel's array is almost sorted, with one 9 out of place. The right panel has a single negative. Watch for the cell that turns red: a real answer, discarded without being looked at.

What to reach for instead. If you can't sort because you must return original positions, use a hash map for O(n), or sort (value, index) pairs and keep two pointers at O(n log n). If values can be negative, a window's shrink step is no longer safe: count with prefix sums and a hash map (LC 560), or find the shortest with prefix sums and a monotonic deque (LC 862).

Same direction is not the same as a window

Day 4 · ask what the gap between the pointers means

The confusing case is two pointers that both move right. Read/write pointers (Move Zeroes) and a window (Max Consecutive Ones III) look identical from a distance: for r in range(n), a second pointer that trails behind, one pass. Run them on the same array and the difference shows up in the gap between the pointers.

def pair_with_sum(a, target):
    """a is sorted. Return (i, j) with a[i] + a[j] == target, or None."""
    i, j = 0, len(a) - 1
    while i < j:
        s = a[i] + a[j]
        if s == target:
            return i, j
        if s < target:
            i += 1          # row i can't reach target: drop it
        else:
            j -= 1          # column j overshoots: drop it
    return None

import math

def shortest_at_least(a, target):
    """Every a[x] >= 0. Length of the shortest run with sum >= target, or 0."""
    best = math.inf
    left = window = 0
    for right, x in enumerate(a):
        window += x                    # grow: take a[right]
        while window >= target:        # valid: record, then try shorter
            best = min(best, right - left + 1)
            window -= a[left]          # shrink: drop a[left]
            left += 1
    return 0 if best == math.inf else best
